# Changelog

PhotoFolio 主题的版本更新记录。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.0.0/)。

## [0.15.1] — 2026-10-11

### Changed
- **灯箱图像分析按需加载**：EXIF 下方新增「圖像分析」触发行（安静的灰色小字 + 下箭头、无框无底色不喧宾夺主，随元信息同组淡入）——图表区（影調/色卡/飽和度/色相）默认收起，**点击展开才探测下载 w_1024 采样图并逐像素统计**；打开与切图不再默认发起探测请求、不再与主图解码/滑入动画争抢主线程，首开与快速连切观感更快；展开/收起带 **max-height + opacity 过渡动画**（与抽屉同曲线同时长；展开走 class 兜底大值、收起先按当前可见高度内联定值再过渡——从固定大值收起会在动画前段无可见变化；`prefers-reduced-motion` 直切）；展开后触发行隐藏、**收起按钮移至分析区底部**（「收起圖像分析」灰色小字 + 上箭头、与触发行同缘左对齐），收起时信息栏**同步回滚到顶部**（与开合过渡同曲线同时长锁步、视口跟随内容收缩上移，不残留空白等待区），桌面端「放得下」的**居中判定在点击瞬间按收起后最终高度立即做出**（fitAdjuster 扣除正在收缩的分析区高度——最终总高在整个过渡期间恒定，同步居中且不翻覆，不等回顶结束才切换），居中采用 **unsafe center + 面板裁切 + 位置补偿**——内容仍高于面板的过渡帧保持居中布局（上下对称裁切），标题/标签按点击前位置实测做 transform 补偿（消除 is-fit 翻转瞬间的向上跳变，滚动出画面时为负值、补偿自动保持其不可见），补偿量为**纯实测驱动**（rect 减去当前补偿反推真实布局位、最终居中位由布局位逐帧实测估计——与 offsetHeight 整数舍入无关，起点精确连续、终点补偿恰好归零、全程无跳变），补偿量随收起进度锁步归零——标题从点击前位置平滑滑向居中位、与图表收缩同段动画，**收起恰为展开的逆向**（safe center 在溢出时顶对齐，居中运动会落到过渡末尾、呈现「收起完才开始居中」的拖尾）；**展开同理**——触发行不再 `display:none` 瞬间移除（内容骤减一行、居中块下移约半行），改为 max-height/边距/透明度随开合平滑收拢（纯 CSS、与图表区同曲线同时长）——布局高度变化连续、居中位移顺滑，展开方向无需 JS 补偿；收起时触发行复现的位移由收起补偿覆盖（实测点上提至触发行 class 切换前）；收起过渡改为**双内联值之间运行**（实测高度 px → 0px、强制 reflow 提交起点值）——与 class 移除同帧提交时过渡会从 class 的 80em 旧值起算、前段高度纹丝不动（启动延迟约 0.3s）的问题就此消除；**加载期不额外显示加载指示**——图表区照常展示（影調/色卡等区块标题与图表框即占位），数据就绪后直接填充，切图时旧图表保持显示、按既有形变过渡替换；展开态跨切图保持（同会话翻照片延续展开）、**关闭灯箱即重置收起**（下次打开回到默认收起、点击才加载）；**关闭期间强制重判「放得下」**（active 守卫跳过会残留过期的 is-fit=false——再打开时详情区 auto 边距把内容挤到中部、标题与 EXIF 之间出现大空隙）；**收起时触发行随开合平滑收拢**（不用 display:none 瞬间移除、上下内边距一并归零——border-box 下 max-height 压不缩内边距，残留内边距条会露出文字行中间一条）

### Fixed
- **iOS/平板窄屏「作品」子导航点不动**：两层原因——① 父项为普通 `<span>`，iOS 只向可交互元素（原生交互元素或声明 `cursor: pointer` 者）派发 click，`.nav-parent` 补 `cursor: pointer`；② **断点边界错位**：平板竖屏恰为 768px，CSS `max-width: 768px` 显示汉堡菜单、JS 却以 `min-width: 768px` 视为桌面端直接返回——两处 JS 断点对齐为 `min-width: 769px`（与样式表严格互补），手风琴可正常展开收起；③ **窄屏子导航展开后箭头不翻转**：hover-ready 只在进入宽屏时武装、回到窄屏不拆除——旋转/缩放往返后残留，配合触屏粘性 `:hover` 让更高特异性的 `transform:none` 规则恒压过 `sub-open` 的箭头旋转（点击导航栏外移走 hover 才恢复）——进入窄屏时同步拆除 hover-ready
- **iPad 横竖屏翻转不切换宽窄样式**：常驻页面的桌面下拉面板与**返回顶部按钮**均为「定位 + transform + 过渡时长>0」模式，恰是 WebKit 旋转后 `clientWidth` 永久取旧值（[Bug 287042](https://wiki.webkit.org/show_bug.cgi?id=287042)）的触发条件——媒体查询随之失效、宽屏样式保持到刷新为止；下拉面板**入场动画移除 transform（改纯透明度淡入）**、返回顶部按钮**隐藏/显示改用 bottom 属性位移**（bottom: -4em ↔ 2em，彻底移除 transform 与 transform 过渡）；旋转导致的断点跨越跳过导航滑出/滑入动画（`screen.orientation` 类型变化判定），菜单面板残留的内联 transition 清理移出动画函数（旋转跳过动画时清理也照常执行）
- **iOS 灯箱切图辉光层闪帧**：Safari 对带 `filter` 的 `<img>` 就地换 src 有合成缺陷（强制重排等方案只能改变闪烁时机、无法根治）——辉光层改为**每张作品一层、新层解码后淡入旧层剪枝**（与背景层同层模型），彻底消除就地换源；**iOS 上整体跳过辉光层**（对齐参考站做法——其在苹果端同样不渲染辉光）：iOS Safari 对过滤图的换源/合成缺陷逐案修补成本高且不稳定，照片无光晕直接显示，其余平台保持四边辉光（检测覆盖 iPadOS 桌面 UA 伪装）；辉光同步**半分辨率栅格化**（盒 50%×50% 网格居中 + `blur(0.5em)` + 2× 放大——视觉等同原 1em，光栅化尖峰约降至 1/16；四边辉光几何经 2× 缩放映射与原布局一致；**scale(2) 并入 transform 内联**——独立 scale 属性与 transform 的合成顺序会把 transform 的位移也放大 2 倍，辉光滑出速度翻倍、与主图拖尾错位（harness 实测 192px vs 主图 96px，修正后逐帧恒差 30px 柔边溢出））；**滑动位移按像素对齐主图**（主图位移百分比按自身照片盒宽解析、竖构图时窄于单元——百分比补偿会导致辉光先于主图移出的拖尾残影）；**辉光淡入改为主图滑入完成后触发**（滑入途中淡入会在落点先于主图显现残影；reduced-motion 无滑入过渡、就绪即淡入）；**切换开始即复位主图揭示标志**（switching 要等滑出结束才置位、缓存命中的新辉光在滑出途中就绪时会穿过门控就地淡入——旧图移出时尾部叠出双影，复位后滑出期间辉光只登记就绪、绝不淡入）
- **灯箱背景毛玻璃淡入卡顿（旧版 Chromium）**：交叉融替期间四角压暗后恢复的过程 = 新层淡入阶段，其满屏 40px blur 的首次光栅化尖峰与淡入动画抢合成器导致掉帧——背景层改为**半分辨率栅格化 + 2× 放大**（半屏盒 + `blur(1.25em)` + `scale(2.2)`：滤镜输出像素 ¼、半径减半、尖峰整体约 1/16，观感与满分辨率等同，纹理内存 ¼）；源图**保持与网格缩略图同 URL（w_800）**——灯箱打开即缓存命中，背景不会因新请求等待而呈现黑色；**窄屏（≤1000px）灯箱主图改用 w_1280**——w_1920 的首次光栅化与背景淡入同窗争抢合成器是剩余尖峰，手机屏约 1080px 宽观感无差、成本约降 2.3×（桌面保持 w_1920）；背景层补 **`will-change: opacity` 钉住合成层**——旧版 Chromium GPU 内存压力下会降级图层、降级期间 opacity 过渡每帧重跑滤镜链（真机 A/B：参考站同样卡顿、未做此提示——本方案若生效则优于参考站；仍卡则换「穿过纯黑逐层淡入淡出」样式）
- **移除 Apple web-app meta 声明**（`apple-mobile-web-app-capable` 等四条）：独立模式由 manifest 接管，普通浏览无副作用（与参考站对齐；真机验证未解决旋转问题、仅排除此假设）
- **iPad Safari 旋转后布局不恢复（根因定位与修复）**：真机逐层诊断确认——**瀑布流卡片图片的内联像素宽度（JS 按当前视口布局写入）把页面最小内容宽度钉在旋转前的值，iOS shrink-to-fit 据此拒绝收缩布局视口**（实测竖屏视口钉在 1006px、媒体查询/档位全部按宽值评估，导航/灯箱/瀑布流整体不恢复；参考站无此机制故正常）——`masonry-container` 补 `overflow-x: hidden` 裁掉页面级横向溢出、打破「内容钉视口 ↔ 视口钉内容」的死循环，视口可收缩到目标宽度、媒体查询翻转、resize 触发重排恢复列数；瀑布流档位判定同步改为 **CSS 变量信号**（样式表媒体查询写入 `--layout-tier`，JS 经 `getComputedStyle` 读取——绕开曾被怀疑的 JS 侧评估陈旧问题；resize/查询 change/延迟重判保留为触发源）；视口 meta 重置兜底保留为双保险
- **窄屏抽屉展开态辉光顶部分割边界**：照片贴顶时辉光顶部 blur 溢出被图片区边缘硬裁（顶部内边距 1em 不足以容纳 1.5~2em 溢出，底部特意留了 2.5em、顶部未留）——展开态经 `:has(.is-open)` 将图片区顶部内边距补到 2.5em，随既有 padding 过渡平滑变化

## [0.15.0] — 2026-10-09

### Added
- **灯箱影调与色彩分析（摄影界标准口径）**：采用摄影教材标准术语与标准分析方法、无外部算法——「影調」区块：结论行 = **经典九调命名**（高調/中間調/低調 × 長調/中調/短調，如「低長調」——高/中/低調由亮度中位数 P50 相对中间灰 18% 灰 ≈ sRGB 118 的位置判定，中位数不受极端像素拉动；長/中/短調由**動態範圍**判定 = P5–P95 跨度换算为「档」，摄影界衡量动态范围的标准单位，P5/P95 去掉两端各 5% 极端像素）· 剪裁警告（≥2% 像素落于 0–5 → **陰影剪裁** / 250–255 → **高光剪裁**，与修图软件同口径）；**合并直方图**（R/G/B 三通道曲线 + 明度分布曲线（金色实线，与通道色区分）——**纯曲线无填充**（天然平滑无锯齿条纹，每通道 256 点固定结构可形变）+ 修图软件同款注释：陰影/中間調/高光三分区底色（分区界 = 中间灰 ±1 档曝光）+ P50 虚线标记 + 两端剪裁三角；原独立的 RGB 直方图区块并入影调区块、明度直方图不再单列）；**區域系統 11 级灰阶**（安塞尔·亚当斯 0–X，感知均匀色阶，括号标出照片 P1–P99 占據區域，标注行直接说明「曝光灰階（0 純黑 → X 純白）」）；**三区占比条**（陰影/中間調/高光三段堆叠 + 百分比文字）；数据行（動態範圍/亮度中位數）；每张图均带说明文字（「直方圖（虚線為亮度中位數）」/「曝光灰階（0 純黑 → X 純白）」标注行）；**切图时图表带连续形变动画**：直方图/飽和度/色相三张 SVG 图在切图时**旧图形与新图形之间线性插值**（rAF 驱动，时长与缓动取自 `--transition-chart` CSS 变量、与曝光灰階括号/占比条同源同节奏）——图形连续变形而非跳变，首绘直接呈现，快速连切时中断上一次过渡从当前中间帧继续变形；**P50 虚线标记与饱和度均值标记同样参与形变**（x 位置随过渡滑动到新位置）；新增**飽和度**区块（HSV 饱和度 0–100% 分布直方图 + 均值标记 + 低飽和/高飽和轴端点标注，定性低飽和/適中/高飽和）与**色相**区块（HSV 色相 0–360° 分布，每段填其色相本色、主色相段高亮，按饱和度加权——灰色无相不参与判定，主色相取 8 个标准色名并沿横向均布标注：紅/橙/黃/綠/青/藍/紫/品紅；**黑白照判定**：平均饱和度 <5% 视为无彩色——结论显示「黑白」、色相图以灰色柱呈现）；新增 `[params.lightbox].saturation` / `.hue` 开关、移除独立的 `histogram` 开关（直方图并入影调区块）；中屏（769–1000px）图表区改为双列网格（**影調/色卡 同行、飽和度/色相同行**——按高度相近配对，色卡更高时影調的直方图弹性补足、不留空缺，四格满铺）

### Changed
- **灯箱切图加载转圈**：新图未缓存时浏览器在 src 加载期间仍显示旧图——现隐藏图片并显示与瀑布流加载指示器同款的转圈，加载完成后再滑入淡入（首开未缓存同样转圈等待）；预加载图片保留引用（Map，按当前图左右邻居裁剪防内存累积）用于同步探测缓存状态，不产生重复请求；加载失败时转圈消失、元信息照常
- **灯箱背景毛玻璃切换对齐参考站灯箱**：灯箱底色改为**不透光纯黑** `rgb(var(--rgb-black))`（移动端高亮屏不再透视站内文字）；背景层改为**每张作品一层 `<img>`（动态创建）**，切换机制与参考站灯箱逐项对齐——旧层**立即**淡出 0.7s（不等新层就绪，加载慢时背景短暂为纯黑底、与参考站一致）、新层就绪后淡入 0.7s（`cubic-bezier(0.4, 0, 0.2, 1)`，即其 duration-700 同款），背景变化与图片切换同刻开始、贯穿整个切换过程；新层淡入完成后移除所有旧层（剪枝定时由淡入时长推导 + 50ms 余量）；新层加载失败时丢弃该层并让上一层淡回；层按 DOM 顺序叠放（新层在后、天然压在上层），回调只操作本层元素——无跨层状态可翻转，快速连切/关闭重开不会串层；**背景与辉光改用缩略图源（w_800）**、主图仍用全尺寸（w_1920）——与参考站一致（其 backdrop 与 blur 占位层均用 thumb），解码快、观感一致；主图后方新增**同框模糊副本辉光层**（参考其 blur 占位层：清晰图盖住内部、模糊溢出边缘形成柔和辉光轮廓，src 随主图同步、加载转圈期间隐藏）——**与主图同尺寸、随主图渲染大小等比变化**（盒恒为整个网格单元、内容经 object-fit: contain 与主图渲染矩形完全重合、不做放大，两侧与上下光晕由 blur 向外溢出提供）；**辉光内容就绪门控**（首开与切图同一条管线）：解码完成前保持隐藏、完成后随主图一起淡入——不先淡入空框、不先于主图独自淡入；图片区改为**单网格单元叠放**两图（同一轨道、同一套 contain 约束，实测矩形完全重合——绝对定位对替换元素的 inset 拉伸不生效、桌面端不对称留白会使定位中心与 flex 中心错位，均不可用），底部间距 2.5em（窄屏抽屉顶起时辉光的模糊过渡在到达裁剪边缘前自然衰减、不露分界线）；主图 `position: relative` 保证盖住辉光（辉光的 filter 层叠上下文会把静态主图压到下层）；滑动动画经 `slideStyle` 同时作用于主图与辉光（移动与淡入淡出同步），滑入阶段辉光只在最终位置淡入（不参与滑入移动，与主图同步到达）；全部过渡响应**减弱动态偏好**（reduced-motion 下直切）；替换原先的双层快速交叉淡入淡出
- **窄屏双列↔单列转换过渡动画**：跨 768px 边界（抽屉模式下信息区双列↔单列）时面板以轻量淡入滑动（0.4s、`panel-inner-layout-in`）柔化内部重排跳变，不扰动图片区；高度重测由既有 resize 处理器覆盖；`prefers-reduced-motion` 时关闭
